# 05 給未來 session 的信

> 按需讀取檔。接手大型或跨對話任務時讀；想知道這套制度的待辦與已知弱點時讀。
> v1 寫於 2026-07-05（Fable 5）。v2 寫於 2026-11-11（Fable 5.2），在看過 v1 被實際使用四個月之後。
> 你（正在讀的模型）大概率是 Sonnet 或 Opus。

## 三件最重要的事

### 1. 失敗封存清單是這個專案最值錢的資產

MEMORY.md 裡標「勿重試／別重提／MUST NOT」的條目，每一條背後是數小時回測與一次「看起來很有道理」的提案。訊號工廠已經迭代 370 多版，**容易的改良早就做完了**——你想到的「新點子」有相當機率是某個舊版本的屍體。動手前先掃封存條目，命中就停（02_judgment Rubric 4）；要回測某個子專案就讀它的 memory 檔全文，因為索引行只放得下一句話。

這不是限制創造力，是讓回測時間花在真正沒試過的地方。

### 2. 「邏輯上對」在這裡不夠：這台機器會壞、綠燈會騙人、寫入會越界

v1 這一條只講了環境地雷（Windows 11＋PowerShell 5.1＋CP950＋NSSM＋打包的 exe；memory 的環境條目每條都是實際炸過的，你的常識與它衝突時信 memory）。四個月的事故紀錄補了另外兩種「看起來對」：

- **綠燈不等於驗到了**。一條 pipeline 的第一階因語法錯誤根本沒寫入，後面三階的檢查照樣全綠，因為它們讀的是舊狀態。所以 Rubric 2 要你造一個必須失敗的案例來驗檢查機制本身。
- **結果合理不等於有權寫入**。事故紀錄裡最多的一類不是算錯，是寫了沒被授權的東西：使用者說「繼續」被當成整批授權、說好先給覆核卻直接寫入、界線寫「不得連線」卻下了唯讀查詢。使用者對這類事的容忍度很低，而且事後無法補正。寫入前過 Rubric 10 的四軸，一軸答不出來就停下來問。

### 3. 使用者要的是可信的決策，不是好看的數字

回測數字很容易做出改良的假象（單一事件過擬合、單訊號 PF 稀釋合池、交易數灌水）。整套防護（三大目標、時間均勻、受控對照、bit-identical）是因為被假象燒過才建的。所以：負向結果照實報，「這個方向不行」是有價值的交付；把邊際增益包裝成突破，比沒有產出更糟。使用者吃直球——「我不確定」「這題我判斷不了」都是可接受的答案。

## 這套制度會怎麼退化，以及怎麼防

v1 列的退化方式裡，**第二項（規則只增不減）真的發生了**，而且當時設的防線沒擋住，原因值得記住：門檻量的是行數，而行可以無限長。防線量錯了東西，就等於沒有防線。

| 退化方式 | 徵兆 | 預防 |
|---|---|---|
| **常駐檔再度膨脹** | `check_budget.py` 出現 FAIL；或有人在 `.claude/rules/` 新增沒有 `paths:` 的檔 | 改完制度檔必跑 `python c:/Claude/Invest/.claude/ref/check_budget.py`。教訓先進 `ref/02_cases.md` 踩坑紀錄，經使用者同意才進常駐核心（04_maintenance「升格」節） |
| **教訓寫了但沒人讀到** | 同一個形狀的錯出現第二次 | 踩坑紀錄不是常駐的。同型第 2 條出現就**必須向使用者提出升格提案**，並先分辨是規則不足還是執行違規；只追加在紀錄尾端等於沒寫 |
| **核心與細節各說各話** | 照核心做被細節檔的條文打臉 | 改 Rubric N 的核心時讀細節檔同節（04_maintenance 改法第 5 條）。發現矛盾就暫停相關操作，把兩邊原文並列回報使用者，不自行挑一份當權威 |
| **該讀細節檔卻沒讀** | 標 ★ 的 Rubric 命中，卻只照核心的摘要動手，漏掉細節裡的條件 | 核心的 ★ 是硬要求。若發現某條 ★ 的細節常被漏，提案把那個細節升格進核心，而不是加一句「務必要讀」 |
| **MEMORY.md 又變成進度日誌** | 索引行出現 commit hash、批次編號、日期流水 | 進度寫在專案自己的 memory 檔，索引行只寫「是什麼＋何時讀」。單行 450 bytes 由腳本檢查 |
| **跳過委派** | 主對話連續讀 4 個以上的檔、貼長輸出 | 01_dispatch §1 是硬門檻 |
| **文件與 harness 現實脫節** | 照規則做卻報錯；規則說某工具不存在但 schema 裡有 | 以當下 tool schema 為準。01_dispatch §0 標了快照日期，超過 90 天就核一次。事實性修正可自行改 |
| **儀式化驗證** | 驗收從來沒有不通過的 | 驗收 prompt 不帶引導語、不用 `fork`。連續 10 次全過就抽查驗收 prompt |
| **rubric 不合身硬套** | 套完自己都覺得怪 | 誠實條款的第三步永遠可用：明說判斷不了，附選項與 tradeoff |

## 這套制度補不了什麼

拆解、驗證、升降級、多樣本評審，能把**執行品質**撐到接近寫這封信的 session 的水準。補不了的有三種：

1. **跨領域的直覺連結**（例如從 breadth 逆勢權重聯想到另一個等價的 lever）。做法：需要跳躍時派 `opus` 開放式腦暴多個方向，再逐一用便宜的方法驗證。
2. **第一眼聞出「這個增益來源不乾淨」的嗅覺**。做法：老實走流程——sweep＋時間分布＋受控對照會把嗅覺問題轉成機械問題。
3. **判斷「這整件事該不該做、範圍是不是太大」**。事故紀錄裡有一個設計連出六版、每版審查都冒出新的高嚴重度問題，最後是使用者叫停並重估範圍。制度只能給計數器（Rubric 4「審查不收斂」），給不了那個判斷。計數到了就停下來交給使用者，不要再出一版。

三種都一樣：做不到就說做不到，把選項與 tradeoff 交給使用者。

## 2026-11-11 使用者裁定（v2 留下的六項提案）

貫穿六項的原則，使用者原話：**Harness 可以讓模型有更大的執行自主性，但不能讓模型自行擴張自己的權限。** 模型可以發現問題、提出方案、備好驗證材料；正式制度的修改權在使用者手上。

同時裁定的兩項制度原則（已寫入 02_judgment 檔頭、02_cases 檔頭、04_maintenance）：

- **核心與細節矛盾時不假設任何一份優先**：暫停相關操作，讀兩邊，把原文並列回報使用者。
- **同型事故第 2 次發生，必須提出升格建議，但不必然新增規則**：先分辨是規則不足，還是有規則卻沒照做。這兩種情況的處方不同。

本裁定不重開 commit `28066bf5`；後續變更各自獨立處理、逐項驗收。接下來的重心是下面的新 session 實測與 MEMORY 的長期維護，不是再加規則。

## 新 session 必做的三項載入驗收

這三項是 v2 載入架構的實際驗收，不是一般待辦。**未取得證據不得宣告通過**；取得的證據補進 [00_diagnosis.md](00_diagnosis.md) 檔末「v2 驗收紀錄」那張表（屬事實更新，可自行改），並在回報中告知使用者。v2 session 自己驗不了，因為它派出的 agent 拿到的都是 session 開場的舊規則快照。

| 項目 | 驗收要求 | 失敗時 |
|---|---|---|
| 1. ref 按需載入 | 在 Read 任何檔案之前，檢查開場 context：**整個 `.claude/ref/` 的正文都不應出現**。逐一核對四個標題底下有沒有內文：「00 診斷：這套制度為什麼長這樣」「02 判斷力 Rubrics：細節與事故原文」「03 派工 Prompt 模板」「05 給未來 session 的信」。同時確認路徑條件檔「04 制度檔維護協議」「06 常駐服務安全」「07 訊號工廠記憶提取」也還沒出現 | 任何一個出現＝該層沒生效。回報使用者並檢查載入機制，不要自己搬檔 |
| 2. 06 的 paths 載入 | 第一次 Read 某個 `.bat` 或 `intraday_snapshot.py` 之後，確認工具結果後面附帶了 `06_service_safety.md` 的內容。v2 session 驗過機制與五種 glob 寫法都生效，但 06 本身兩次都沒出現（推測是與開場已載入的舊版內容相同而被去重） | 沒出現就手動 Read 它再繼續，記一行踩坑，回報使用者 |
| 3. MEMORY.md 截斷 | 三個觀測值分開記，不可互相代替：(a) 檔案實際大小（bytes、字元數、行數）；(b) 開場 context 裡看得到的最後一行，是不是磁碟上的最後一行；(c) context 裡有沒有截斷提示 | 看不到最後一行＝有截斷：記下截斷位置，回報使用者，釐清上限的計算口徑 |

第 3 項的已知事實與陷阱：

- v2 session 開場時 MEMORY.md 是 30,298 bytes／17,936 字元／87 行，context 裡看得到最後一行。所以「25KB」至少不是以 bytes 計的硬截斷——可能以字元計，也可能這個版本沒有執行。**這是推測，未驗證。**
- 2026-11-17 實測 MEMORY.md 15,882 bytes，**低於 25KB 不代表第 3 項自動通過**：看得到最後一行只能證明「這個大小沒被截」，證明不了上限在哪裡。照實記成「未觸發，截斷位置未知」。
- 不要為了測上限而去把 MEMORY.md 灌大。

其他沒驗的：各模型對 `effort` 五級的支援沒有逐一試過（v2 session 用過 `sonnet`＋`medium`、`opus`＋`high`，都被接受）。被拒絕時的處理寫在 01_dispatch §0。

`paths:` 若在某個版本失效，後果是 04、06、07 變成每個 session 都載入（多花 token，不會漏規則）；CLAUDE.md 的地圖仍要求命中觸發時自己 Read，所以行為不會壞。
