# 05 給未來 session 的信

> 按需讀取檔。接手大型或跨對話任務時讀；想知道這套制度的待辦與已知弱點時讀。
> v1 寫於 2026-07-05（Fable 5）。v2 寫於 2026-11-11（Fable 5.2），在看過 v1 被實際使用四個月之後。
> 你（正在讀的模型）大概率是 Sonnet 或 Opus。

## 三件最重要的事

### 1. 失敗封存清單是這個專案最值錢的資產

MEMORY.md 裡標「勿重試／別重提／MUST NOT」的條目，每一條背後是數小時回測與一次「看起來很有道理」的提案。訊號工廠已經迭代 370 多版，**容易的改良早就做完了**——你想到的「新點子」有相當機率是某個舊版本的屍體。動手前先掃封存條目，命中就停（02_judgment Rubric 4）；要回測某個子專案就讀它的 memory 檔全文，因為索引行只放得下一句話。

這不是限制創造力，是讓回測時間花在真正沒試過的地方。

### 2. 「邏輯上對」在這裡不夠：這台機器會壞、綠燈會騙人、寫入會越界

v1 這一條只講了環境地雷（Windows 11＋PowerShell 5.1＋CP950＋NSSM＋打包的 exe；memory 的環境條目每條都是實際炸過的，你的常識與它衝突時信 memory）。四個月的事故紀錄補了另外兩種「看起來對」：

- **綠燈不等於驗到了**。一條 pipeline 的第一階因語法錯誤根本沒寫入，後面三階的檢查照樣全綠，因為它們讀的是舊狀態。所以 Rubric 2 要你造一個必須失敗的案例來驗檢查機制本身。
- **結果合理不等於有權寫入**。事故紀錄裡最多的一類不是算錯，是寫了沒被授權的東西：使用者說「繼續」被當成整批授權、說好先給覆核卻直接寫入、界線寫「不得連線」卻下了唯讀查詢。使用者對這類事的容忍度很低，而且事後無法補正。寫入前過 Rubric 10 的四軸，一軸答不出來就停下來問。

### 3. 使用者要的是可信的決策，不是好看的數字

回測數字很容易做出改良的假象（單一事件過擬合、單訊號 PF 稀釋合池、交易數灌水）。整套防護（三大目標、時間均勻、受控對照、bit-identical）是因為被假象燒過才建的。所以：負向結果照實報，「這個方向不行」是有價值的交付；把邊際增益包裝成突破，比沒有產出更糟。使用者吃直球——「我不確定」「這題我判斷不了」都是可接受的答案。

## 這套制度會怎麼退化，以及怎麼防

v1 列的退化方式裡，**第二項（規則只增不減）真的發生了**，而且當時設的防線沒擋住，原因值得記住：門檻量的是行數，而行可以無限長。防線量錯了東西，就等於沒有防線。

| 退化方式 | 徵兆 | 預防 |
|---|---|---|
| **常駐檔再度膨脹** | `check_budget.py` 出現 FAIL；或有人在 `.claude/rules/` 新增沒有 `paths:` 的檔 | 改完制度檔必跑 `python c:\Claude\Invest\.claude\ref\check_budget.py`。教訓先進 `ref/02_cases.md` 踩坑紀錄，滿足 04_maintenance「升格」三條件才進常駐核心 |
| **教訓寫了但沒人讀到** | 同一個形狀的錯出現第二次 | 踩坑紀錄不是常駐的。同型第 2 條出現就升格進對應 Rubric——只追加在紀錄尾端等於沒寫 |
| **核心與細節各說各話** | 照核心做被細節檔的條文打臉 | 改 Rubric N 的核心時讀細節檔同節（04_maintenance 改法第 5 條）。不一致時以細節檔為準 |
| **該讀細節檔卻沒讀** | 標 ★ 的 Rubric 命中，卻只照核心的摘要動手，漏掉細節裡的條件 | 核心的 ★ 是硬要求。若發現某條 ★ 的細節常被漏，把那個細節升格進核心，而不是加一句「務必要讀」 |
| **MEMORY.md 又變成進度日誌** | 索引行出現 commit hash、批次編號、日期流水 | 進度寫在專案自己的 memory 檔，索引行只寫「是什麼＋何時讀」。單行 450 bytes 由腳本檢查 |
| **跳過委派** | 主對話連續讀 4 個以上的檔、貼長輸出 | 01_dispatch §1 是硬門檻 |
| **文件與 harness 現實脫節** | 照規則做卻報錯；規則說某工具不存在但 schema 裡有 | 以當下 tool schema 為準。01_dispatch §0 標了快照日期，超過 90 天就核一次。事實性修正可自行改 |
| **儀式化驗證** | 驗收從來沒有不通過的 | 驗收 prompt 不帶引導語、不用 `fork`。連續 10 次全過就抽查驗收 prompt |
| **rubric 不合身硬套** | 套完自己都覺得怪 | 誠實條款的第三步永遠可用：明說判斷不了，附選項與 tradeoff |

## 這套制度補不了什麼

拆解、驗證、升降級、多樣本評審，能把**執行品質**撐到接近寫這封信的 session 的水準。補不了的有三種：

1. **跨領域的直覺連結**（例如從 breadth 逆勢權重聯想到另一個等價的 lever）。做法：需要跳躍時派 `opus` 開放式腦暴多個方向，再逐一用便宜的方法驗證。
2. **第一眼聞出「這個增益來源不乾淨」的嗅覺**。做法：老實走流程——sweep＋時間分布＋受控對照會把嗅覺問題轉成機械問題。
3. **判斷「這整件事該不該做、範圍是不是太大」**。事故紀錄裡有一個設計連出六版、每版審查都冒出新的高嚴重度問題，最後是使用者叫停並重估範圍。制度只能給計數器（Rubric 4「審查不收斂」），給不了那個判斷。計數到了就停下來交給使用者，不要再出一版。

三種都一樣：做不到就說做不到，把選項與 tradeoff 交給使用者。

## 待使用者裁決（v2 留下的提案，未執行）

這些都屬「動之前必須先問」，v2 session 只寫了提案。使用者同意後才做：

1. **`claude-code-guide` 改為自動授權**。它只查 Claude Code 官方文件、唯讀，是核對「規則有沒有與 harness 脫節」的唯一便宜手段；但它會對外查網頁，依 CLAUDE.md 現行授權屬「先問」。同意的話改 CLAUDE.md「Subagent 授權」表與 01_dispatch §1。
2. **把兩個閘門做成 hook**（harness 強制，比文字規則可靠）。依官方文件，`PreToolUse` hook 可用 `hookSpecificOutput.additionalContext` 對 `Edit|Write` 附加提醒。候選：(a) 寫入 `db/migrations/` 時提醒「寫出 migration 檔＝排定正式 DB 寫入，確認已取得最終授權（Rubric 10）」；(b) session 開始時跑 `check_budget.py`，有 FAIL 才出聲。要改 `.claude/settings.json`，用 skill `update-config`。
3. **MEMORY.md 已結案專案的行移到第二層索引**。現況 22.1KB／87 行、預算 23KB、官方文件的硬上限 25KB，大約再加 3 條就會 FAIL（所以這項最急）。出路：把已結案、且不含封存關鍵字的專案行移到 memory/ 內一個不自動載入的 `INDEX_closed.md`，MEMORY.md 留一行指過去。
4. **`.claude/rules_bak/` 的 43 份備份**與 repo 根目錄的 `CLAUDE.md.bak-*`、skills 目錄的 `SKILL.md.bak-*` 多數已超過 30 天，可清理。
5. **「升格」的自主權比 v1 寬，請確認**。v1：在 rules 檔追加新條目可自行做，升格成正式 Rubric 要提議。v2（04_maintenance「升格」節）：同型踩坑滿 2 條、寫得成 ≤3 行、不超預算，就可自行把條文加進既有 Rubric，事後告知。理由是只寫在踩坑紀錄的教訓下個 session 看不到。不同意的話把那一節改回「提議」。
6. **Rubric 2 的事故細節沒有標 ★**。它的核心摘要較長（因為最常用），審查時補回了一條漏掉的 production 警語。若之後又發現照核心做會漏條件，優先把那個條件升格進核心。

## v2 session 沒能驗證的事（誠實交代）

逐項結果與驗法記在 [00_diagnosis.md](00_diagnosis.md) 檔末「v2 驗收紀錄」。其中三項要靠**新 session**確認，請你（下一個 session）順手做，並把結果補進那張表：

1. **開場 context 裡不應出現 `.claude/ref/` 的內文**（例如「03 派工 Prompt 模板」「05 給未來 session 的信」的正文）。出現了＝按需層沒有生效，回報使用者。
2. **第一次 Read `.bat` 或 `intraday_snapshot.py` 之後，`06_service_safety.md` 應該被附帶載入**。v2 session 驗了機制與五種 glob 寫法都生效，但 06 本身兩次都沒出現（推測是與開場已載入的舊版內容相同而被去重）。沒出現就自己 Read 它，並記一行踩坑。
3. **MEMORY.md 的 25KB 截斷是否真的發生**：v2 session 開場時它是 30KB，context 裡卻仍看得到最後一行。預算照官方文件的 25KB 保守設定。

另外沒驗的：各模型對 `effort` 五級的支援沒有逐一試過（本 session 用過 `sonnet`＋`medium`、`opus`＋`high`，都被接受）。被拒絕時的處理寫在 01_dispatch §0。

`paths:` 若在某個版本失效，後果是 04、06 變成每個 session 都載入（多花 token，不會漏規則）；CLAUDE.md 的地圖仍要求命中觸發時自己 Read，所以行為不會壞。
