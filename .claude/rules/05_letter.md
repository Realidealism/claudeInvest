# 05 給未來 session 的信

寫於 2026-07-05，Fable 5 制度化 session。你（正在讀的模型）大概率是 Sonnet 或 Opus。這封信講的是使用者沒問、但我認為對這個環境最重要的三件事，以及這套制度會怎麼壞掉。

## 三件最重要的事

### 1. 失敗封存清單是這個專案最值錢的資產

MEMORY.md 裡標「勿重試/別重提/MUST NOT」的條目，每一條背後是數小時回測與一次「看起來很有道理」的提案。這個專案的訊號工廠已經迭代 350+ 版，**容易的改良早就做完了**——你想到的「新點子」有相當機率是編號 v3xx 的舊屍體。動手前先掃封存條目，命中就停（[02_judgment.md](02_judgment.md) Rubric 4）。這不是限制你的創造力，是讓你把回測時間花在真正沒試過的地方。

### 2. 這個環境的地雷是「邏輯上對、在這台機器上壞」

Windows 11 + PowerShell 5.1 + CP950 + NSSM 服務 + 打包的 exe。memory 裡的環境條目（.bat 純 ASCII、goto 不用巢狀 exit /b、system Python 路徑、殺 process 前確認 parent、rebuild exe 要 --clean）每一條都是實際炸過的。當你的常識與 memory 條目衝突時，**信 memory**。反過來也一樣重要：verified 過的環境事實要寫回 memory，你的下一個 session 跟你一樣沒有肌肉記憶。

### 3. 使用者的真實目標是「可信的採用決策」，不是「好看的數字」

回測數字很容易做出改良的假象（overfit 單一事件、單訊號 PF 稀釋合池、交易數灌水）。使用者建了整套防護（三大目標、時間均勻、受控對照、sanity bit-identical）就是因為被假象燒過。所以：負向結果照實報，「這個方向不行」是有價值的交付；把邊際增益包裝成突破，比沒有產出更糟。使用者吃直球——「我不確定」「這題我判斷不了」都是可接受的答案（[02_judgment.md](02_judgment.md) 誠實條款）。

## 這套制度最可能的退化方式與預防

| 退化方式 | 徵兆 | 預防 |
|---|---|---|
| **跳過委派**：覺得「自己讀比較快」，主 context 又被灌爆 | 主對話連續讀 4+ 檔、貼長輸出 | [01_dispatch.md](01_dispatch.md) §1 是硬門檻不是建議；違反的代價在 [00_diagnosis.md](00_diagnosis.md) 問題 2 |
| **規則只增不減**：每次踩坑加一條，rules 檔變成沒人讀完的長文 | 檔案超過精簡門檻、規則開始互相重複 | [04_maintenance.md](04_maintenance.md) 精簡門檻；追加教訓用一行格式不是一段散文 |
| **文件與現實脫節**：工具改版、路徑變了，rules 還在指舊東西 | 照規則做卻報錯 | 以當下 tool schema / repo 實況為準，查證後修事實性內容（可自行改），順手在踩坑紀錄留一行 |
| **儀式化驗證**：形式上派了驗收 agent，但 prompt 帶引導語（「確認一下應該沒問題」），agent 附和 | 驗收從來沒有不通過的 | 驗收 prompt 用 [03_templates.md](03_templates.md) T5 的「立場：找問題不是背書」；驗收連續 10 次全過本身就是要抽查的訊號 |
| **rubric 不合身硬套**：遇到 rubrics 沒覆蓋的情境，硬選一條套用 | 套完自己都覺得怪 | 誠實條款的第三條路永遠可用：明說判斷不了，附選項與 tradeoff 給使用者 |
| **harness 預設與專案規則對撞**：harness 說「別自己 spawn agent」，[01_dispatch.md](01_dispatch.md) §1 說「一律派 Explore」 | session 開頭臨場猜聽誰的、兩邊各做一半 | 看 CLAUDE.md「Subagent 授權（覆蓋 harness 預設）」節（唯讀自動、`general-purpose` 先問）；那裡沒寫到的衝突當場問使用者，並把裁定寫回制度檔 |

## 誠實的交代：這套制度補不了什麼

拆解、驗證、升降級、多樣本評審，能把**執行品質**撐到接近本次 session 的水準。補不了的是：跨領域的直覺連結（例如從 breadth 逆勢權重聯想到 gate-百分位等價 lever 這種跳躍）、以及第一眼就聞出「這個增益來源不乾淨」的嗅覺。遇到這兩類情境，你的正確動作不是模仿，而是：老實走流程（sweep + 時間分布 + 受控對照會把嗅覺問題轉成機械問題）、需要跳躍時派 opus 開放式腦暴多個方向再逐一便宜驗證、真的不行就告訴使用者這題需要他下判斷。
