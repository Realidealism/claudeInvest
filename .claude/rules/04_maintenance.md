# 04 制度檔維護協議

適用對象：CLAUDE.md、`.claude/rules/*.md`、memory/。目的：讓制度能安全演化，而不是只增不減地腐化。

## 可自行改（不必先問使用者）

- 在 [02_judgment.md](02_judgment.md) 末尾「踩坑紀錄」**追加**教訓（格式見下）
- 更新 memory/（循系統 memory 協議：先查重、更新既有檔優先於開新檔、MEMORY.md 只放一行索引）
- 修正 rules 檔中**已查證失效**的路徑/工具名/模型名（例如工具改版）——改前備份，且只改事實性內容不改規則本身。**僅限 `.claude/rules/*.md`**；CLAUDE.md 內的任何內容（包括失效路徑）仍屬下一節「必須先問」

## 動之前必須先問使用者

- 改 CLAUDE.md 任何內容（含路由表）
- 刪除或**改寫** rules 檔的既有規則（追加新條目不在此限）
- 刪 memory 檔、合併壓縮 MEMORY.md
- 改 `.claude/settings.json` 或 hooks（既有 skill `update-config` 亦適用時優先用它）

## 改法（硬規則）

1. 改任何既有檔前先備份：`cp <file> <file>.bak-YYYYMMDD`（同目錄）。同檔同日已有備份就不重複。
2. 新規則必須寫成「**觸發條件 → 動作**」，並附至少一個例子。抽象形容詞（「保持高品質」「小心一點」「盡量」）禁止入檔——寫不出觸發條件的規則就是還沒想清楚，先放踩坑紀錄醞釀。
3. 新規則與既有規則衝突時，不能只加新的——要嘛改舊的（先問使用者），要嘛在新規則寫明優先序。
4. 備份檔（`*.bak-*`）超過 30 天可提議清理。

## 教訓寫回哪裡、什麼格式

踩到坑（做錯了、被使用者糾正、發現規則沒覆蓋的情況）後，當下就寫，不要等任務結束：

- **環境/專案事實類**（API 行為、編碼陷阱、資料特性）→ memory/（既有協議）
- **工作方法類**（該派工沒派工、驗證方式錯了、該問沒問）→ [02_judgment.md](02_judgment.md)「踩坑紀錄」，一行格式：

```
- YYYY-MM-DD | 情境一句話 | 當時錯誤假設 | 正確做法 | 一般化規則（觸發條件→動作）
```

- 判斷這條教訓會影響多數 session 而非個案 → 額外向使用者提議升格成正式 Rubric 或 CLAUDE.md 規則

## 精簡門檻（防止只增不減）

| 訊號 | 動作 |
|---|---|
| MEMORY.md > 60 行 | 提議壓縮（歷史 baseline 行合併，規則見 [00_diagnosis.md](00_diagnosis.md) 問題 1） |
| 單一 rules 檔 > 250 行 | 提議拆分或壓縮 |
| 踩坑紀錄 > 10 條 | 提議歸納：相似條目合併成 Rubric，個案細節移到 memory/ |
| 兩條規則說同一件事 | 提議合併，保留較具體的那條 |

壓縮永遠是「**提議**」——列出要刪/併的具體條目給使用者確認後才執行，執行前備份。
