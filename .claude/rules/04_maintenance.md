# 04 制度檔維護協議

適用對象：`CLAUDE.md`、`.claude/rules/*.md`、`.claude/ref/*`、memory/（路徑見 `.claude/ref/00_diagnosis.md` 名詞節）。目的：讓制度能安全演化，而不是只增不減。

## 兩層結構與預算

| 檔 | 何時載入 | 位元組預算 |
|---|---|---|
| `CLAUDE.md` | 每個 session | ≤ 10,000 |
| `.claude/rules/01_dispatch.md` | 每個 session | ≤ 10,000 |
| `.claude/rules/02_judgment.md` | 每個 session | ≤ 16,000 |
| `MEMORY.md` | 每個 session | ≤ 23,000，且單行 ≤ 450 |
| `.claude/rules/04_maintenance.md`、`06_service_safety.md` | 碰到 `paths:` 所列檔案時 | 各 ≤ 9,000 |
| `.claude/rules/07_signal_memory.md` | 碰到 `paths:` 所列檔案時 | ≤ 3,000 |
| `.claude/ref/*.md` | 你自己 Read 時 | 單檔 ≤ 60,000 |

- **量法**：`python c:/Claude/Invest/.claude/ref/check_budget.py`。改完任何制度檔或 MEMORY.md 後必跑；輸出有 `FAIL` 就還沒完成。不要用目測或行數判斷。
- MEMORY.md 的上限是硬的：依官方文件，harness 只載入它的前 200 行或前 25KB（腳本以 180 行、23,000 bytes 把關），超過的部分之後的 session 看不到，而新條目正好都加在檔尾。
- `.claude/rules/` 下任何 `.md`（含子目錄）只要沒有 `paths:` frontmatter 就會每個 session 全量載入。**不要在 `.claude/rules/` 新增檔案**；按需讀的內容放 `.claude/ref/`。真的需要新的路徑條件檔 → 屬「必須先問」，並同步改 `check_budget.py` 的 `ALLOWED_RULES`。
- **你 context 裡的制度檔是 session 開始時的版本**（subagent 拿到的也是）。本 session 改過的檔，以磁碟上的為準；派驗收 agent 時叫它從磁碟 Read。

## 可自行改（不必先問）

- 在 `.claude/ref/02_cases.md` 最下方「踩坑紀錄」**追加**一行教訓
- 更新 memory/ 的個別檔；在 MEMORY.md 新增或更新**自己這次寫的那一行**（寫的時候就要符合下方「MEMORY.md 寫法」）
- 修正 rules／ref 檔中**已查證失效的事實**（路徑、工具名、模型名、參數）。只改事實，不改規則。例：`01_dispatch.md` §0 寫某工具不存在，而你當下的 tool schema 裡有 → 改 §0 並更新快照日期。
- **草擬**升格提案（診斷、草案文字、預算影響）。正式改 Rubric 要先問，見下方「升格」節

## 動之前必須先問使用者

- 改 `CLAUDE.md` 任何內容（包括修正失效路徑）
- 刪除或**改寫** rules／ref 檔的既有規則；在 `.claude/rules/` 下的檔新增任何條文（含升格）
- 把內容在常駐與按需之間搬動、改預算數字、改 `paths:` 條件、在 `.claude/rules/` 新增檔案
- 刪 memory 檔；合併或壓縮 MEMORY.md 裡別的 session 寫的行
- 改 `.claude/settings.json` 或 hooks（用 skill `update-config`）

## 改法（硬規則）

1. **先備份**：`cp <檔案> .claude/rules_bak/<檔名>.bak-YYYYMMDD`（MEMORY.md 也備到這裡）。同檔同日已有備份就不重複。備份放 `rules_bak/` 不放 `rules/`。
2. **新規則寫成「觸發條件 → 動作」＋至少一個例子**。抽象形容詞（「保持高品質」「小心一點」「盡量」）禁止入檔——寫不出觸發條件就是還沒想清楚，先留在踩坑紀錄。
3. **衝突**：新規則與既有規則衝突時，不能只加新的。要嘛改舊的（先問），要嘛在新規則寫明誰優先。
4. **編號固定**：Rubric 1–12、01_dispatch 的 §0–§6 被 memory 與 skill 用編號引用，不可重排、不可重用。新 Rubric 用下一個號碼（13）。
5. **核心與細節同步**：改了 `rules/02_judgment.md` 的 Rubric N → 讀 `ref/02_cases.md` 同節，確認沒有變成互相矛盾。任何時候發現核心與細節互相矛盾（不論是誰造成的）→ 暫停與該 Rubric 相關的操作，把兩邊原文並列回報使用者；不自行挑一份當權威，也不自行改掉其中一邊。
6. **改完驗收**：(a) `python c:/Claude/Invest/.claude/ref/check_budget.py` 全 PASS；(b) `git status --short` 確認只動到打算動的檔（`.claude/` 被 gitignore，新增的 ref 檔要 `git add -f` 才會進版控）；(c) 派 fresh agent read-back（`01_dispatch.md` §6）。
7. `rules_bak/` 內超過 30 天的備份可提議清理（提議，不自行刪）。

## 教訓寫回哪裡

踩到坑（做錯了、被使用者糾正、發現規則沒覆蓋）後當下就寫，不等任務結束：

- **環境／專案事實**（API 行為、編碼陷阱、資料特性）→ memory/ 的個別檔
- **工作方法**（該派工沒派、驗證方式錯了、該問沒問）→ `.claude/ref/02_cases.md` 踩坑紀錄最下方，**一行**，新條目單條 ≤ 600 bytes（2026-11-11 當天及以前的既有條目不回溯、不要去截短）：

```
- YYYY-MM-DD | 情境一句話 | 當時錯誤假設 | 正確做法 | 一般化規則（觸發條件→動作）
```

正例：`- 2026-10-20 | 界線為「不得連線正式 DB」期間為查版本下了唯讀 SELECT | 以為唯讀查詢不算連線 | 版本從 docker inspect 取得 | 界線寫「不得連線」→ 連線本身被禁止，與是否唯讀無關`
反例：把具名公司、commit hash、三輪審查經過全寫進這一行（那些寫進 memory 檔，這行只留檔名當指標）。

## 升格（踩坑紀錄 → 常駐核心）：提議制

只寫在踩坑紀錄的教訓下個 session 看不到；但制度的修改權在使用者手上。你可以發現問題、草擬修改、備好驗證材料；**正式修改 Rubric 一律先取得使用者授權**。

**觸發：同一個形狀的踩坑出現第 2 條 → 必須在當次回報提出升格提案**（不可只把第 2 條記進紀錄就結束）。提案固定四項：

1. **診斷：規則不足，還是執行違規？** 先查常駐核心有沒有已涵蓋這個情況的條文。
   - 有條文而沒照做＝執行違規 → 不提新增規則；改提「那條為什麼沒被命中」（埋太深、觸發條件寫得不像當時的情境）與怎麼改善。
   - 沒有條文，或觸發條件涵蓋不到＝規則不足 → 往下。
2. **現有 Rubric 哪裡不足**：引用條文原文，指出缺哪個觸發或哪個動作。
3. **草案**：加進哪一條 Rubric、確切文字（≤3 行，觸發 → 動作，附例子）。
4. **預算影響**：加入前後的位元組數。

使用者同意 → 寫入，並在踩坑條目行尾標「→已折入 Rubric N」。不同意或沒回應 → 不寫入，行尾標「→已提案未採納（日期）」，之後不重複提同一案。

反例：自己判斷條件都滿足就把條文加進 Rubric、事後才告知（2026-11-11 使用者裁定不核可）。

## MEMORY.md 寫法

每行一個 memory：`- [標題](檔名.md) — 這是什麼；什麼情況要讀它`，單行 ≤ 450 bytes（約 150 個中文字）。

- **可以留在索引行**：封存關鍵字與它禁止什麼（「勿重試」「MUST NOT 再提 X」）；一句最會改變行為的教訓。
- **不可以放索引行**：commit hash、逐日進度、批次編號、裁定編號、檔案路徑清單。這些寫進該 memory 檔。
- **進行中專案**：索引行寫「（進行中）做什麼；現況讀檔末」。之後每次更新進度都改那個 memory 檔，不改索引行。
- **baseline**：任何時刻只允許 1 行標粗體 `**(當前)**`（腳本以粗體計數；其他行提到這個詞時不要加粗）。新 baseline 上位時，同時把前一版併入「訊號工廠版本正史」那一行。
- **失敗封存條目不壓縮、不合併**，逐條保留。訊號工廠、評分、攻防主題的條目逐條留在 memory 的 `INDEX_signal_factory.md`；MEMORY.md 只留一行指標。
- **訊號工廠主題的新記憶**：索引行加在 `INDEX_signal_factory.md`；使用者的工作偏好仍加在 MEMORY.md。

正例：`- [447 家分類重判（進行中）](project_industry_rejudge.md) — 逐家 membership 裁定，分批進行；開批前讀檔末現況`

| 訊號 | 動作 |
|---|---|
| `check_budget.py` 出現 FAIL | 當下處理。常駐檔超標：提議把最長的例子或次要條文搬到 `ref/`（先問）。MEMORY.md 超標：提議壓縮（先問） |
